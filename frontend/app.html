How a face is protected

Six layers between the camera and the database.

zero plaintext at rest

    Subject details

    Three samples are captured and averaged into one template.

    Claim an identity

    Enter the e-mail you enrolled with, then prove it with your face.

    One-to-many search

    Every encrypted template is decrypted in memory only, compared, then discarded.

    Cryptographic trace

    Follow one capture through every step. Nothing is saved.

    Enrolled subjects

    Names are decrypted for authorised operators. E-mails are masked.

    Raw database rows

    All an attacker gets by stealing biometric.db: ciphertext, nonces, wrapped keys and HMACs.

    Audit log

    Each entry is chained to the previous one with HMAC-SHA256.

    Key encryption keys

    Rotation re-wraps every DEK under a new KEK; template ciphertext is untouched. Retiring an unused key crypto-shreds old backups.

    Transport key

    RSA-3072 public key fingerprint (SHA-256). Compare it with the server to rule out a man-in-the-middle.
